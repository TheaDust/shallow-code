# Builder 效率调整与分组阈值

## 2026-11-06 的默认选择

功能组上限调整为 **10 条原子需求、16 个原始场景、40,000 字符**。三项限制同时生效；模块边界、依赖顺序及单个超限原子的完整保留规则沿用现有合同。Grouper 仍须按业务内聚和复杂度决定实际包边界，容量上限不是要求装满。

阈值定义位于 `src/scheduler.ts` 的 `DEFAULT_FEATURE_GROUP_THRESHOLDS`。确定性参考分组、Grouper 输入、提交 schema、校验与运行事件使用同一份定义。

复现命令（输出目录须与输入目录分开）：


脚本只读取需求，不调用模型或读取正式测试。输出包括规范化需求副本、源文件 SHA-256、各候选阈值的完整成员和容量数据；`results.json` 可用于复核表格。

## 自测收口

普通实现包集中完成相关修改，再按 `target/filter` 执行局部测试；共享接口、权限、种子和持久化修改扩展到受影响模块。存在明确全局回归风险时仍应扩大检查。

控制器依据当前需求树的实现进度，为最后一个待实现包设置 `finalImplementation`；尚有树内需求未完成时不授予该标记。实现提示的动态尾部据此声明阶段，固定系统规则只定义一次。最后一个实现包与 baseline 的完整应用开发统一执行一次 `all`、项目类型检查和构建；当前源码状态已有成功记录时沿用结果。

此标记用于 Builder 开发检查，不改变独立 Verifier、修复目标验收或最终重放开关，也不向 Builder 暴露正式测试和私有验收产物。

## 完整请求计时

共享 Pi 执行层保留原有 `modelMsTotal` 的流开始至消息结束语义，并新增：

| 字段 | 含义 |
| --- | --- |
| `modelRequestMsTotal` | 完整对话请求累计耗时，包含流开始前等待与失败尝试 |
| `modelWaitMsTotal` | 完整请求耗时减去流式响应耗时；不是独立可相加的阶段 |
| `modelRequestCount` | 本次调用内的请求次数，含重试 |
| `modelErrorCount` | 已结束的失败或取消请求数 |
| `modelErrorMsTotal` | 失败请求耗时，是完整请求累计耗时的子集 |

请求开始通过 SDK 的 payload hook 记录，并保留现有 payload 转换；结束优先采用 SDK 从 provider stream 创建时起计量的 `durationMs`。即使请求在收到流开始前失败，也能计入完整时间。对话外的 SDK 独立摘要/压缩不归入这些对话请求指标。

未结束请求在进度快照中按当前时间计算，不因重复读取快照而重复累加。Worker 被强制终止时，只能保留最后一次进度心跳采样的时长；尚未采样的尾段无法由旧快照还原。续用会话的计时只统计本次调用，不继承旧调用的请求计时。

人类日志显示完整请求、流开始前等待、流式响应、失败请求和工具耗时。历史日志没有新增字段时继续使用原有显示，不把旧 `modelMsTotal` 解释成完整请求耗时。
