## ARCHITECTURE.md 交接约定

在项目根维护 ARCHITECTURE.md，作为新会话定位代码和识别跨模块约束的短索引。默认目标约 8 KiB；最多 200 行且不超过 16 KiB，按实际 UTF-8 字节数计算。索引的价值在于减少查找和避免破坏既有行为；超过 8 KiB 时先合并重复条目，不要为了字节数删除入口、同步点或测试指针。

已有索引时，开始工作先读本包涉及的领域条目，再按条目给出的路径、符号和测试核对代码；不要先递归扫描源码树。需求与平台合同决定目标行为。已有应用而笔记缺失时建立首版；实现或修复改变已有约定时，只更新实际改变的条目并删除过时描述，没有变化时保持不动。发现路径、符号或测试与代码不符时，先做一次窄搜索，再把结果补回条目；不要新建第二份索引，也不要把未核实的猜测写进去。

按领域组织，不按目录堆叠。每个领域条目至少写清以下三项，缺失的写“无”：

- **入口**：项目相对路径和至多 1–3 个关键符号，说明该领域的权威实现位置。
- **同步点**：需要同时修改的调用方、共享类型/状态、种子入口或测试 mock，各至多 1–3 项。
- **测试**：覆盖该领域行为的主要测试路径；没有独立测试时写“无”并说明现有检查位置。

共享路由、端点、种子段或状态形状按领域或区段拆开写，不要只指向整个文件；每项给出对应同步点或测试。例如共享 API 路由文件按“路由组 → 领域模块”分行，种子文件按“种子段 → 领域”分行，并附对应测试或 mock。

必要时再写：

- **关键约束**：只记单个文件难以说明、且跨模块修改必须保留的事实，例如权威状态与派生值的分工、持久化边界、原子性、权限判断位置或同步关系。一条约束写一次，附源码位置；必要时用一句解释原因。
- **必要准备**：种子定义位置、初始化时机，以及互斥初态或对象归属确实需要说明的公开准备路径。同类准备合并记录；影响续做的当前限制简述位置和影响，解决后删除。

字段全集、逐条 API、控件文案、算法步骤、测试用例清单和常规命令以源码、测试与 package.json 为准，索引只给定位入口。同一事实只保留一处；任务进度和本次检查结果写入回执。长表格单元格和超长行同样计入内容长度限制。

### 交接完成条件

新增或修改条目后，核对相关路径、符号和事实，并执行一次大小检查（在项目根运行）：

```sh
node -e "const fs=require('node:fs'); const text=fs.readFileSync('ARCHITECTURE.md','utf8'); const bytes=Buffer.byteLength(text,'utf8'); const lines=text.split(/\r?\n/).length; console.log({bytes,lines}); if(bytes>16384||lines>200) process.exit(1);"
```

超过 8 KiB 时先去重、合并同类条目，将可查细节替换为源码指针；超过硬上限必须继续压缩并复测。只在本次交接完成时检查一次，中间编辑不必反复测量；不能仅以行数或字符数判断大小。检查项报告实测字节数与行数；只有确需保留的独立跨模块约束才使用 8–16 KiB 的空间。
