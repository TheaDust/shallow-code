【可访问 Web 交互契约】

未指定时使用原生语义，不把某个场景的 DOM 结构推广到所有页面。

产品名称和首页标识以需求为依据；若提供首页链接且需求未指定其名称，用 Home 的可访问名。空状态使用需求允许的一种主提示，辅助说明提供其他必要信息；只要求一个空状态时，不堆叠同义提示。需求明确要求的多个控件或提示仍分别保留。

输入控件使用符合用途的原生类型：文本、密码、多行、搜索、复选和单选。普通单选下拉及需求称为 combo box/combobox 的选择控件优先使用脚手架混合 Combobox：以真实原生 select 保存值、提交表单并兼容浏览器 selectOption，激活后只暴露当前控件的一组可见、可点击 option；不得把它简化成只有隐藏原生选项或只有自定义输入的单一路径。只有需求明确要求可输入搜索、动态建议或创建选项等该组件无法表达的交互时才实现专用 ARIA combobox/listbox，并正确关联可见 option。选项的可访问名称与页面显示名保持一致，但原生选项及未展开选项不能制造跨控件 role=option 冲突，也不能与业务结果精确文案形成全局歧义。需求给出的 label 要关联到输入，placeholder 另行实现；仅给 placeholder 时也让输入可访问。校验错误显示在页面中，不只依赖浏览器原生校验气泡。未指定角色时，操作用 button，页面导航用带 href 的 link；要求 heading 时用真实 <h1>–<h6>。打开对象的方式依需求，可由条目、button 或 link 承担；同名操作可以重复，但用 article、row、dialog 等单层容器区分，避免嵌套交互控件。表格按需求使用 table、row、cell。

需求指定 form、region、group 容器及可访问名时，用对应的语义结构（具名 `<form>`、具名 `<section>`、`<fieldset><legend>` 或具名 `role="group"`），通过 aria-label、指向标题的 aria-labelledby 或 legend 提供需求原名；容器名与内部字段 label 分别保留。

要求 menu/menuitem 时提供相应角色与键盘行为；菜单内若要求 button 就保持 button。图标操作有稳定 aria-label；需求或场景要求悬停显示的次要操作应在悬停后出现，并支持键盘聚焦；未明确要求时保持入口可发现、可直接操作，不根据参考图额外增加悬停步骤。下拉、单选、多选使用可访问的 option、radio、checkbox；禁用的原生控件用 disabled，非原生交互控件用 aria-disabled 并实际阻止操作，恢复可用时同步更新状态。展开、按下、选中状态及时更新 ARIA，动作名随状态变化时同步更新。对话框有可访问名称，开启后背景不可操作，关闭后恢复合理焦点；关闭的对话框卸载其说明与操作节点，不让隐藏文案抢在当前页面的可见状态之前成为同名文本首项。

操作后检查实际对象和状态；刷新、重进保留需求规定的状态。通知使用 status 或 alert，但提示不能代替结果；提示中的操作必须可点击。表单、搜索区和对话框的容器名称不要遮蔽内部输入控件名称。需求规定视觉或 DOM 属性时也实现。

继承应用中的公共组件拷贝也要遵守上述生命周期：检查现有 Dialog 的关闭分支，原位卸载说明、子内容与操作，保留打开、焦点隔离和关闭后的焦点恢复。能力安装不会覆盖已有不同内容，不能把再次安装当作组件升级。管理型对话框保存后先呈现更新的列表，保留管理视图供继续操作，再由明确的关闭动作结束；一次性确认或表单是否关闭按当前需求判断，不在通用 Dialog 中统一决定。

继承应用的独立实体详情若以唯一标识或 tag 区分对象，将该身份提供为精确可访问 heading，描述标题仍单独保留。重复提交失败时，保留输入，并在同一失败表单上下文呈现一个可见的已有对象标识或入口。人数、数量等结果使用完整的数值与实体单位文字，归属于对应实体的明确容器；核对增加、减少及刷新后的实际数值。

补充身份标题、计数表达和持久状态时，保留需求规定的描述标题、原数据值与操作控件的角色、名称和作用域。给既有身份展示增加标题语义，保持该标识的精确文本匹配唯一；完整计数放在同一实体的独立展示位置，保留原操作按钮名称、内容和选中状态。详情的关联字段以标签和实际值共同呈现，列表、详情及刷新后保持同一记录。唯一键冲突在当前错误表单中核对输入与已有标识，再验证未产生重复对象；退出表单后的列表不能代替错误上下文。撤销后的持久标记与恢复后的可用状态均由实际记录驱动，成功提示只表达本次动作。

全局控件在首页、登录后及实体详情保持需求定义的操作范围；局部搜索使用自己的入口和作用域。跨页面检查进入真实详情并提交操作。需求明示地址标识当前状态时，默认状态也写入地址，并核对取消操作、刷新和直接重开。撤销后的状态标记按需求持久化；返回登录页面时保留需求已声明的公共登录入口及表单角色，其他仍有效的会话保持可用。

首屏和切页时，将页面入口与正文、列表加载分开：仅依赖已确认身份、路由和权限的导航与表单结构随目标视图立即呈现，保持 role、可访问名、label 和所属容器稳定；不因无关列表请求未完成而隐藏入口。确实依赖未就绪数据的操作保留同一控件并暂时禁用，忙碌状态可以并存，不用加载占位替换它。权限未知时先确认；身份或对象变化后重新校验，不能沿用上一身份或对象的授权来展示受保护入口或内容。数据就绪和操作后，按需求规定的时机更新当前视图。
