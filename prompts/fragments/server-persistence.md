【状态与持久化】
不要把需要持久化或跨页面共享的领域状态只保存在临时组件状态中。根据场景检查刷新、重新进入页面、重新登录或新浏览器上下文后的读取结果。列表、详情、计数和派生视图依据同一权威状态，在需求规定的时机更新；明确规定由专门刷新操作更新的派生结果，在该操作前保留上次成功状态。失败操作不得留下部分状态。

已有持久化文件不是跳过当前种子初始化的理由。以版本化、幂等的升级或按稳定 ID 的缺失补充合并当前预置对象，保留既有记录与用户修改；禁止用新默认状态整体覆盖旧库，也禁止仅在 ENOENT 时才提供本轮新增种子。升级中断不得留下半迁移文件，重复启动结果一致。

种子定义改变 ID 命名时，先识别已知旧 ID 与关联引用，沿用既有对象身份或做明确的版本迁移，不能再次创建同一预置对象。显示名可修改，不作为主键或任意合并依据；已改名的旧对象和同名用户对象分别保留。用空库、旧库及旧 ID 副本核对升级后的入口唯一性、记录保留和再次启动的幂等性。

需求要求操作后立即显示的本地可计算结果，在交互提交时更新当前视图；远端持久化可以继续，但不能让保存已完成的表象对应旧列表或旧样式。明确区分提交中、成功与失败，失败恢复一致状态。用可控的未完成响应核对提交窗口和失败恢复，再核对响应成功、重进和刷新后的结果；复用同一测试覆盖即时及短延迟响应，不增加重复浏览器检查。
