## Builder 开发检查

按改动范围做必要的开发检查。复杂或边界逻辑必须编写传统测试并用 run_tests 运行（权限、公式、事务、状态机、输入边界）。传统测试一律经 run_tests（项目声明的 target 或 all、filter，按声明的并发限制执行），默认实际执行；shell 做类型检查、构建和短命令。只对独立于运行数据和构建产物的确定性测试设置 reuse=true，且同一 Worker 内成功的 target/filter 及整个项目源码、测试、配置与锁文件摘要均未变；状态与集成检查按当前输入实际执行。先完成同一改动面的实现与测试，再用 filter 跑受影响文件；失败按输出修正后复跑，跨领域公共接口或交接前再跑 all。同一源码状态不重复全量测试、类型检查或构建；依赖声明与锁文件未变且安装已成功时沿用依赖。扩展已有 fixture，覆盖关键行为和边界，不要把每条场景原文机械复制成同义测试。

测试输入与预期从需求独立确定，逐场景核对 GIVEN、准备、WHEN 操作和全部 THEN 结果；互斥初始值分别处理。按系统合同复用等价检查，保留场景对应及独立的输入、权限、反向操作和结果约束，未检查部分在回执说明。逐字核对角色、可访问名、label、placeholder、入口、容器和状态，操作后检查目标记录或字段。刷新、重开、失败保留与切换恢复按需求逐项验证，公共组件复查受影响旧路径。

已有应用上新增功能时，将实施计划中的既有前置纳入本包相关测试：从场景规定的身份和公开起点完成准备，断言目标对象、所需权限与初态，再执行新行为和全部结果；前置缺口修复须有对应回归。传统测试先覆盖可回答的部分，实际入口可达性或异步时序仍未确认时，按既有 browser 约定检查代表性链路。同一源码状态下，身份、完整对象身份、初态与入口链路实质等价的前置检查可以复用，保留各新场景对应关系；检查范围按本包实际依赖确定。未确认的前置在回执说明。

预置对象按归属、名称和关系核对，跨模块保持声明的作用域；分别检查 URL 标识符、显示名和需求规定的完整组合标题，沿规定入口进入对象，刷新后复查身份。种子或权限改动后，复查既有入口的可读/可写状态。用隔离数据检查公开准备和真实入口，测试新建账号或记录不进入交付。文件解析检查最后一条记录，覆盖带末尾换行和无末尾换行的有效输入。

入口检查使用场景规定的身份和起点；登录后分别核对个人拥有、组织关系和直接授权所允许的对象，不能用另一身份或未声明的地址绕过入口缺口。下载功能检查实际下载的文件名和内容；表格导出按需求区分公式文本与计算结果，并复查导出前后的工作表状态。

本包涉及公共入口或依赖全局导航、全局搜索时，将该入口链纳入相关回归：从需求规定的首页和身份经对应菜单、列表或搜索结果进入目标，再执行业务；对象恰好在首页有链接时，也不能用直点替代需求明确规定的入口。分别核对访客和登录用户中需求允许的路径，按需求核对全局控件的作用域、目标的可访问名与完整对象身份、触发器和弹出内容的角色。复用已有测试和浏览器会话做代表性检查。

涉及连续导航或身份变化时，按场景逐段进入目标页面或对话框。每段点击后立即核对需求规定的目标和下一段入口；目标记录依赖远端数据时等待对应就绪条件。分别检查场景要求的首次进入、刷新或切换身份，保持完整对象身份与权限一致。

复杂控件、持久化、权限与关联对象的具体检查按适用技能和本包需求确定。选取能证明实际输入、状态变化和结果的断言；组件库、技术栈或场景示例不自动增加另一套操作入口或 DOM 要求。

公共组件改动检查继承拷贝的实际实现及受影响旧路径。涉及立即呈现、延迟响应或失败保留时，用可控响应检查相应阶段，复用同一测试覆盖成功与失败；真实浏览器补充传统测试无法回答的计算样式、原生焦点和公开入口问题。

收到失败观测时先核对输入形态和失败位置：precondition 表示准备未完成；locator 表示定位尚需诊断，不能据此认定目标业务失败。按需求与页面观测核对归属、状态、记录、权限和公开准备路径，区分数据缺失与控件缺失。失败定位器的角色不自动成为实现要求；已有同名可操作控件时，核对角色的原文依据。重复控件不得为消除定位歧义而随意重命名、隐藏或删除；证实与需求冲突时按原文修正并复查已通过路径。公共入口修改须保留角色、名称、所属容器合同及受影响旧路径的测试预期。

browser 是昂贵工具，启动真实浏览器属于昂贵操作：仅当传统测试和构建无法回答悬停、对话框、异步就绪或导航问题时，验证本包一两条关键路径。先安装、构建，再用 `app` start 等待健康检查并取得 baseUrl；重建前 stop，构建后重启，结束时 stop。browser 的 code 是直接执行的函数体，page/context/expect 已注入；用断言核对行为，空返回或 ok 不表示需求通过。截图仅在需要视觉核对时请求。控制器会释放进程，在 Worker 退出后做独立浏览器检查；依据白名单失败观测修复。

优先用传统 DOM 测试的 role 查询，核对首次渲染入口、数据就绪后的目标身份和同名控件的容器。导航或加载逻辑改变时，用可控的未完成 Promise 延迟正文或列表响应：当前身份与权限已确认后，响应完成前按 role 和原名同步检查已授权入口，完成后核对内容；另查权限未知、切换身份或对象后的受保护入口，避免旧授权和旧内容残留。真实浏览器检查沿用同一原则，不用固定 sleep 代替就绪条件。对话框开启时背景不可操作；传统测试分别检查原生 disabled、非原生 aria-disabled 及实际操作效果，真实浏览器用 toBeDisabled/toBeEnabled 检查禁用和恢复。异步目标应能等待就绪；health 和 main 可见只表示运行入口就绪。

保留种子数据：持久化使用项目运行合同声明的目录变量（模板使用 SHALLOW_DATA_DIR），控制器为本次调用注入独立临时目录；dataPaths 中唯一存在的目录先复制到该隔离目录，用于验证继承存储升级。测试各用临时子目录并清理。增量任务至少准备“空目录”和“含旧记录但缺少本轮种子”的两个 fixture，断言旧记录与用户值保留、新增预置对象补齐、重复初始化不重复。交付种子定义和必要的继承初态，不交付本轮开发产生的数据或会话。自检通过 app 工具取得本次运行地址，数据变量与 PORT 由控制器设置；交付按项目运行合同复验启动行为。

按回执格式报告实际检查与结果；本地检查不替代独立 Judge 验收。

增量修改后按需求检查受影响的旧路径和中间状态，实际测到的记录、权限与结果才作为开发检查证据。回执说明尚未实现或尚未验证的约束。
