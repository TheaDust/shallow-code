## Builder 开发检查

按改动范围做必要的开发检查。复杂或边界逻辑必须编写传统测试并用 run_tests 运行（权限、公式、事务、状态机、输入边界）。传统测试一律经 run_tests（frontend/backend/all、filter、单 worker），默认实际执行；shell 做类型检查、构建和短命令。只对独立于运行数据和构建产物的确定性测试设置 reuse=true，且同一 Worker 内成功的 target/filter 及整个项目源码、测试、配置与锁文件摘要均未变；状态与集成检查按当前输入实际执行。先完成同一改动面的实现与测试，再用 filter 跑受影响文件；失败按输出修正后复跑，跨领域公共接口或交接前再跑 all。同一源码状态不重复全量测试、类型检查或构建；依赖声明与锁文件未变且安装已成功时沿用依赖。扩展已有 fixture，覆盖关键行为和边界，不要把每条场景原文机械复制成同义测试。

测试输入与预期从需求独立确定，逐场景核对 GIVEN、准备、WHEN 操作和全部 THEN 结果；互斥初始值分别处理。按系统合同复用等价检查，保留场景对应及独立的输入、权限、反向操作和结果约束，未检查部分在回执说明。逐字核对角色、可访问名、label、placeholder、入口、容器和状态，操作后检查目标记录或字段。刷新、重开、失败保留与切换恢复按需求逐项验证，公共组件复查受影响旧路径。

已有应用上新增功能时，将实施计划中的既有前置纳入本包相关测试：从场景规定的身份和公开起点完成准备，断言目标对象、所需权限与初态，再执行新行为和全部结果；前置缺口修复须有对应回归。传统测试先覆盖可回答的部分，实际入口可达性或异步时序仍未确认时，按既有 browser 约定检查代表性链路。同一源码状态下，身份、完整对象身份、初态与入口链路实质等价的前置检查可以复用，保留各新场景对应关系；检查范围按本包实际依赖确定。未确认的前置在回执说明。

预置对象按归属、名称和关系核对，跨模块保持声明的作用域；分别检查 URL 标识符、显示名和需求规定的完整组合标题，沿规定入口进入对象，刷新后复查身份。种子或权限改动后，复查既有入口的可读/可写状态。用隔离数据检查公开准备和真实入口，测试新建账号或记录不进入交付。文件解析检查最后一条记录，覆盖带末尾换行和无末尾换行的有效输入。

入口检查使用场景规定的身份和起点；登录后分别核对个人拥有、组织关系和直接授权所允许的对象，不能用另一身份或未声明的地址绕过入口缺口。下载功能检查实际下载的文件名和内容；表格导出按需求区分公式文本与计算结果，并复查导出前后的工作表状态。

本包涉及公共入口或依赖全局导航、全局搜索时，将该入口链纳入相关回归：从需求规定的首页和身份经对应菜单、列表或搜索结果进入目标，再执行业务；对象恰好在首页有链接时，也不能用直点替代需求明确规定的入口。分别核对访客和登录用户中需求允许的路径，检查全局控件位于 banner、目标链接的可访问名与完整对象身份、菜单触发器和菜单内容的角色。复用已有测试和浏览器会话做代表性检查，不额外遍历无关对象。

涉及账户、组织或仓库入口时，在正式构建的应用中从首页登录，逐段检查工作台对象入口、账户菜单到安全设置与登出确认、组织列表到对象详情。每段点击后立即核对目标页面或对话框及下一段已授权具名入口，不能先等待无关列表或正文请求完成再检查导航；目标记录确实依赖列表数据时再等待列表就绪。分别检查首次进入、刷新和切换身份后的入口及权限；菜单和页面导航控件须与所属页面一起稳定呈现。

Hash 路由链路须在点击完成后立即观察到目标视图；专门覆盖菜单选择后菜单同步卸载的路径。脚手架混合 Combobox 分别用浏览器原生 selectOption 和“点击 combobox 后点击可见 option”核对同一值与变更事件；专用 ARIA combobox 按需求核对输入、可见 option 与选择结果。多个组合框含同名选项时，页面角色查询只出现当前展开的一组 option。检查业务结果的精确文字不会被其他列表行或未展开选项制造 strict 歧义；对话框同时核对可访问 dialog 与兼容类入口。

公共组件改动检查继承拷贝的实际实现。关闭 Dialog 后用文本和 DOM 查询确认说明、表单与操作已卸载，再检查重开和焦点恢复。管理型保存按当前需求检查直接更新的列表与明确关闭动作。涉及保存后的立即呈现时，用可控响应分别覆盖即时、150ms、500ms 和失败分支；这些时序在同一传统测试中完成，浏览器仅补传统测试无法回答的计算样式或原生焦点问题。颜色核对真实计算背景色及刷新结果，种子升级核对旧 ID、旧记录保留、无重复预置对象和再次启动。

收到失败观测时先核对输入形态和失败位置：precondition 表示准备未完成；locator 表示定位尚需诊断，不能据此认定目标业务失败。按需求与页面观测核对归属、状态、记录、权限和公开准备路径，区分数据缺失与控件缺失。失败定位器的角色不自动成为实现要求；已有同名可操作控件时，核对角色的原文依据。重复控件不得为消除定位歧义而随意重命名、隐藏或删除；证实与需求冲突时按原文修正并复查已通过路径。公共入口修改须保留角色、名称、所属容器合同及受影响旧路径的测试预期。

browser 是昂贵工具，启动真实浏览器属于昂贵操作：仅当传统测试和构建无法回答悬停、对话框、异步就绪或导航问题时，验证本包一两条关键路径。先安装、构建，再用 `app` start 等待健康检查并取得 baseUrl；重建前 stop，构建后重启，结束时 stop。browser 的 code 是直接执行的函数体，page/context/expect 已注入；用断言核对行为，空返回或 ok 不表示需求通过。截图仅在需要视觉核对时请求。控制器会释放进程，在 Worker 退出后做独立浏览器检查；依据白名单失败观测修复。

优先用传统 DOM 测试的 role 查询，核对首次渲染入口、数据就绪后的目标身份和同名控件的容器。导航或加载逻辑改变时，用可控的未完成 Promise 延迟正文或列表响应：当前身份与权限已确认后，响应完成前按 role 和原名同步检查已授权入口，完成后核对内容；另查权限未知、切换身份或对象后的受保护入口，避免旧授权和旧内容残留。真实浏览器检查沿用同一原则，不用固定 sleep 代替就绪条件。对话框开启时背景不可操作；传统测试分别检查原生 disabled、非原生 aria-disabled 及实际操作效果，真实浏览器用 toBeDisabled/toBeEnabled 检查禁用和恢复。异步目标应能等待就绪；health 和 main 可见只表示运行入口就绪。

保留种子数据：持久化使用 SHALLOW_DATA_DIR，控制器为本次调用注入独立临时目录；若交付已有 `backend/data` 或 `backend/.data`，控制器会先把它复制到该隔离目录，用于验证继承存储升级。测试各用临时子目录并清理。增量任务至少准备“空目录”和“含旧记录但缺少本轮种子”的两个 fixture，断言旧记录与用户值保留、新增预置对象补齐、重复初始化不重复。交付种子定义和必要的继承初态，不交付本轮开发产生的数据或会话。自检用 ARC_EXTRA_PORTS=0 与探针 PORT，交付按本次平台合同复验仅设置 PORT 的启动行为。

按回执格式报告实际检查与结果；本地检查不替代独立 Judge 验收。

增量修改共享组件时，用传统测试复查已通过路径，并以少量真实浏览器检查关闭 Dialog 的实际 DOM、完整人数与对应实体、失败表单的标识和输入、管理保存后的更新列表。全局搜索在登录后与真实详情再次提交，局部搜索仍从原入口可用；地址需要状态标识时包含默认状态。复用已有会话和确定性检查，在有限响应延迟及拒绝时核对即时结果、回滚与刷新；记录实际测到的状态，不以回执或重开后的结果替代中间契约。
