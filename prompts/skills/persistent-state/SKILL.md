# 状态与持久化

从需求确定权威状态、派生结果、更新时机和需要跨越的生命周期。选择项目已有且满足作用域的存储方式；跨用户共享状态与仅当前浏览器状态分别处理。列表、详情、计数和派生视图读取同一权威记录；明确要求专门刷新操作更新的结果，在该操作前保留上次成功状态。

操作按需求完整成功或保持失败前的有效状态。即时反馈、提交中、成功和失败分别表达。需求要求立即显示的本地结果，用可控的未完成响应检查提交窗口，再核对失败恢复、成功读取和刷新；远端响应完成后的正确状态不能证明此前的即时结果。

共享初始数据与单场景 GIVEN 分开。扩展预置记录时按稳定身份补充缺失对象，保留既有记录、用户修改和对象关系。存储已存在时仍处理本轮新增种子；互斥场景初态通过公开业务操作分别准备。

改变 ID 或存储结构时，核对旧 ID 和引用的迁移，初始化及升级可重复执行。显示名和主键分别维护，已改名的预置对象与同名用户对象分别保留。用空数据、含旧记录但缺本轮种子的继承数据、重复初始化核对保留、补充与唯一性。

数据目录、环境变量和启动方式采用当前项目运行合同。开发检查使用隔离数据，交付包含种子定义与迁移逻辑。刷新、重进、重新登录或新浏览器会话的检查范围以场景要求为准。
