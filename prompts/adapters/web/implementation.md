## 全新项目的缺省栈

已有代码或脚手架沿用其技术栈、目录、路由和状态存储。仅空项目缺省 React + Vite + TypeScript，后端缺省零依赖原生 http；依赖精确锁定版本并更新项目锁文件。路由方案按页面直达、刷新、嵌套与服务端渲染等实际需求选择，并与项目启动和资源响应一致。导出的 props、领域类型及 API 载荷给出显式类型。按项目运行合同读取 PORT、提供就绪检查和公开入口；测试使用项目已声明的工具和目标，模板前端使用 Vitest + @testing-library/react。

控制器放入的通用最小脚手架提供运行配置、基础工具和任务无关 UI primitives，不代表任何业务需求已经实现；先替换空白占位内容，再完成当前需求。按实际项目目录定位已有工具、组件和权威状态，复用适合当前合同的能力。模板的 `frontend/src/ui/` 提供可访问控件，`frontend/src/lib/` 与 `backend/src/lib/` 提供基础工具；具体目录与工具可用性由项目现状决定。先用 `list_capabilities` 核对批准能力及目标目录，适用时通过 `install_capability` 安装，不覆盖已有不同文件。只有现有实现和适用的批准能力无法可靠满足当前需求时，才从 npm 安装公开、任务无关的通用库，精确锁定版本并更新 lockfile；不得安装含成品页面、业务流程、当前任务领域模型或模板数据的套件，不得从 git URL、任意远程脚本或未批准的 Pi package 加载代码。

需求明确规定的入口、角色、可访问名、label、placeholder、菜单、错误、数量、所属容器及状态，按其所属控件或文本逐字实现，不得缩写、加长、同义替换或翻译；引号中的对象名和示例值不自动成为控件名。logo 等返回首页入口的角色和可访问名以需求明示为准。菜单和对话框按需求顺序开放操作，不额外藏入口或增加确认；具体控件语义遵守本次交互契约。

需求声明全局页头时，使用顶层 `<header>`（banner），与 `<main>` 主内容区区分；全局导航和全局搜索保留其声明的作用域。局部 header 表达所在区域的标题。菜单容器与打开它的按钮、页面标题与同名导航链接分别保留各自角色；布局和入口的具体结构由需求及既有设计决定。

页面入口依据已确认的身份与权限呈现，不等待无关数据；依赖未就绪数据的操作保留控件并暂时禁用，等待期间给出忙碌状态并防止重复操作。失败提供可恢复反馈，列表与详情按需求保持一致。需求文字和场景优先于既有代码及失败定位器；参考图只辅助页面结构、布局和视觉关系，不增加功能要求，排除广告、浏览器界面和无关数据。文字明确规定的视觉或布局约束仍须实现。
