## 项目运行合同

目标应用沿用项目已有目录与技术栈，安装、构建和启动按下方声明的命令与 cwd 执行。新建应用使用控制器提供的 Web 模板。
本轮运行配置作为固定输入，交付中的 shallowcode.config.json 保持与下方声明一致。需要调整运行方式时，先更新配置，再启动新一轮开发与验收。
应用读取 PORT 环境变量，在控制器分配的端口启动。运行环境和命令以项目配置为准。
{{EXTRA_PORTS_SECTION}}
生成期验证使用独立探针端口 PORT={{PROBE_PORT}}；{{RESERVED_PORT_CLAUSE}}每次检查结束后停止你启动的服务进程。
前端沿用项目的 API 配置，新建模板使用同源相对路径；运行端口须可配置。
应用在 {{BROWSER_PATH}} 提供浏览器入口。入口返回成功的 HTML 并可在浏览器打开；具体页面内容、控件与角色按需求实现。静态文件路径基于项目运行方式解析。未知资源与 API 返回错误响应，服务保持运行。
需求声明的页面 URL 必须支持直接打开和刷新，并恢复对应视图。hash 路由保留完整 hash；既有应用使用 pathname 路由时，合法前端路由的 GET 请求须返回可渲染的 HTML 入口并加载对应视图，不能按缺失静态文件返回 404。不存在的 API 和资源仍返回错误响应。
